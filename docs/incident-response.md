# Incident Response

The incident response process focuses on restoring customer impact first
and performing detailed investigation afterward.

## Incident Process

1. Detect the incident.
2. Assess customer impact.
3. Assign an incident owner.
4. Mitigate the immediate impact.
5. Monitor recovery.
6. Identify the root cause.
7. Document the incident.
8. Create follow-up actions.

## Severity

Severity should be determined based on customer impact, business impact,
scope, and duration.

Tier-1 services require faster response because failures can affect a large
number of customers.

## Incident Metrics

Teams should track:

- Time to detect
- Time to acknowledge
- Mean time to recovery
- Customer impact
- Number of recurring incidents

## Post-Incident Review

A post-incident review should focus on system improvements rather than
individual blame.

Follow-up actions may include code changes, monitoring improvements,
automated tests, architectural changes, or operational process changes.
